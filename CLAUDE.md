# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Symbiont — плагин для Claude Code: «живой паспорт проекта». Майнит конвенции/граф/профиль качества из кода любого проекта и подаёт их в сессии через хуки, MCP и скиллы. Ядро — TypeScript под Bun, без демонов и портов (всё событийное: просыпается от хука, работает, умирает). Полная концепция и аксиомы дизайна — `CONCEPT.md`; продуктовое описание — `README.md`.

Репозиторий — сам себе носитель: плагин установлен на этом же проекте (dogfooding), паспорт приходит в SessionStart-сводке автоматически.

## Команды

```bash
bun test                              # вся батарея (930+ тестов)
bun test tests/store.test.ts          # один файл
bun test --test-name-pattern "имя"    # один тест по имени
bun run scripts/bundle.ts             # сборка устанавливаемого артефакта plugin/ (dist+wasm+манифесты)
bun run scripts/canary.ts             # сквозной смок всех хук-каналов реальными процессами (исходники)
bun run scripts/canary.ts --dist      # тот же смок против собранной формы plugin/dist
bun run scripts/canary.ts --dist --node # он же рантаймом поставки (манифесты артефакта зовут node)
bun run scripts/selflint.ts           # структурный само-линт (+ полнота и свежесть бандла)
bun run src/passport/cli.ts <путь>    # ручная сборка паспорта проекта
bun run src/miner/cli.ts <путь>       # только майнер (слой 0)
```

Перед релизом (`plugin update`): бамп версии → `bun run scripts/bundle.ts` → `git add plugin` → `bun test` (0 fail) + `bun run scripts/canary.ts --dist` (9/9) + `bun run scripts/canary.ts --dist --node` (9/9) + `bun run scripts/selflint.ts` (консистентен; ловит несвежий бандл и артефакт, не доехавший в git).

Устанавливается ТОЛЬКО `plugin/` (source в marketplace.json), и артефакт ОБЯЗАН лежать в git: маркетплейс Claude Code умеет только git-источники, поэтому клон репозитория без `plugin/dist` приезжает без единой строки кода. Правило `dist` в `.gitignore` якорится корнем (`/dist`) именно поэтому — без якоря оно накрывало артефакт, и дефект был невидим: игнорируемое не показывается в `git status`.

Линтера/форматтера нет — стиль охраняется собственным гейтом Symbiont и тестами.

## Дисциплина релиза

- Версия в `.claude-plugin/plugin.json` бампается каждый релиз; коммиты — `feat(vX.Y.Z): description` **на английском и в общих чертах**. Репозиторий публичный, история коммитов видна всем: тема называет ЧТО изменилось, тело — зачем, без внутренних подробностей, замеров, имён владельца и деталей устройства. Обоснование решения живёт в комментарии у кода, а не в публичной истории, — там ему и место, потому что читают его вместе с кодом.
- Перед `plugin update`: полный `bun test` + `bun run scripts/canary.ts`.
- `plugin.json` править только редактором/Edit-тулом — PowerShell ломает UTF-8/BOM.
- Заявление «починено/работает» — только с выводом реально запущенной проверки.

## Архитектура

Три этажа + петля (см. `CONCEPT.md` §4): **Паспорт** (артефакты) ← читает **Машина подачи** (хуки/MCP), пишет **Петля самообучения**, критичное принуждает **Машина принуждения** (гейты).

Карта каталогов по этажам:

- **Майнинг паспорта**: `src/miner/` — слой 0 (статистика, любой язык, ноль хардкода; `walk.ts` пропускает производные зоны двумя путями: список имён (`vendor`/`vendors`/`third_party`/…) и консервативный разбор корневого `.gitignore` — проект сам объявляет свои производные каталоги, конфига не нужно; `packs.ts` — оси конвенций как ДАННЫЕ: ось описывает ВЫБОР, который предлагает язык (f-строки или .format, `[]` или `array()`, `:=` или `var`, метод на указателе или на значении), а вердикт по ней выводят числа проекта через тот же `tierOf`. Форма записи — одна популяция (`all`) плюс признак первой формы (`isA`): два независимых счётчика расходились бы на перекрытиях вроде `==` внутри `===`); `src/layer1/` — слой 1 (AST через tree-sitter WASM; `symbols.ts` — оглавление файла (символы с границами строк и ценой выемки) снимается ТЕМ ЖЕ разбором, что и метрики, и ложится в индекс: подача синхронна, а грамматики асинхронны, поэтому разбор в момент подачи невозможен в принципе. Свежесть проверяется хэшем содержимого, расхождение = отказ выдавать границы, а не «почти верные» строки); `src/layer2/` — слой 2 (LLM-вербализация неписаных правил); `src/passport/` — сборка паспорта: `build.ts` (оркестратор), `signals.ts` (**единственное** место, где определено «что такое БД/SEO/тесты…» — stack и profile берут сигналы отсюда, не дублировать), `profile.ts`, `stack.ts`, `roles.ts`, `constitution-derive.ts`.
- **Граф**: `src/graph/` — код-граф (`imports.ts` + `graph.ts`: импорты→рёбра→PageRank; языковые пакеты импортов — ДАННЫЕ: строка таблицы на язык, покрыты JS-семейство, Python, PHP, Go, Java/Kotlin/Scala, C#, Rust, Ruby, C/C++, Dart, Lua; отвергнутые языки перечислены с причиной в `NO_IMPORT_LANGS`, расхождение таблиц ловит селф-линт «ровность языков». Резолв — три механизма, все на данных проекта: **по объявленному** (`package a.b` / `namespace A\B` в самих файлах → PSR-4 и пакеты Java/C# без чтения composer.json), **суффиксный с требованием единственности** (хвост пути; при нескольких копиях побеждает ближайшая ПО РАССТОЯНИЮ в дереве, равенство = нет ребра) и **ссылки по имени типа** (форма name: `extends`/`new X`/`X::`/тайп-хинты/класс строкой → индекс типов, объявленных проектом, с семантикой пространств языка — для стеков на автозагрузке, где импортов почти нет: Yii 1.x, WordPress-классика, Rails/Zeitwerk; голая строка разрешается только в глобальный тип, как делает автозагрузчик). Извлечение осталось регэкспами сознательно: грамматика улучшила бы извлечение, а не резолв, зато протянула бы асинхронность WASM через весь синхронный путь; согласие двух путей сторожит `tests/imports-ast.test.ts` — те же файлы разбираются грамматикой слоя 1 и множества спецификаторов обязаны совпасть), co-change прецеденты (`cochange.ts`) из git-истории, и доменный граф сущностей (`entities.ts`: контент md/html/yaml как узлы, перелинковки как рёбра — сироты/достижимость/битые/дубли анкоров). Встроенный markdown внутри YAML-полей (frontmatter-CMS) парсится как ссылки: ссылка — это ссылка независимо от контейнера. `graph.ts` также: персонализированный PageRank от сида задачи (`personalizedPagerank`, буст сида ×50, self-loop 0.1 — канон aider) и `taskRelevantNeighbors` (ранжирование по ЛИФТУ perso/global — подавляет god-узлы, поднимает специфично притянутое сидом; питает «связанные по задаче» в JIT). `heat.ts` — «тепло» узлов (influence maps): касание узла греет (forward-decay, полураспад 3 дня, остывает между сессиями), тепло входит вторым тиром сида PPR (×10 недавно тронутым — контекст недавней работы), задел под hotspot слоя дрейфа; «горячие узлы» в /sym-status.
- **Ядро состояния**: `src/core/` — `db.ts` (**единственная** форма доступа к хранилищу: подмножество API поверх bun:sqlite ИЛИ node:sqlite, семантика node приведена к bun — промах `.get()`, boolean/undefined, busy_timeout; прямой импорт драйвера где-либо ещё запрещён и ловится селф-линтом) и `runtime.ts` (предпосылки к окружению: какой рантайм есть на машине, загрузка драйвера, скрытый спавн); `store.ts` (журнал фактов, модель Datomic: факты не удаляются, а вытесняются через `superseded_by`; идентичность факта — `keyOf` = «область|предмет до тире»); `ratings.ts` (Glicko-пара рейтинг+отклонение); `schedule.ts` (FSRS-расписание перепроверок); `data-root.ts` (резолв корня данных: `--data` → env `CLAUDE_PLUGIN_DATA` → выведенный стабильный каталог → `.data/` в dev-режиме); `salsa.ts` (хэш-мемоизация пересборок); `models.ts` (адаптивный вектор моделей для СВОИХ LLM-вызовов: приоритет семейств по интенту deep/routine, АЛИАСЫ вместо пиннинга версий — CLI резолвит в последнюю, доступность выучивается из реальных вызовов, кэш `model-availability.json`; три состояния — доступна / нет доступа (403/404) / **лимит исчерпан** (429 или слова о лимите: уходит в хвост вектора на срок и возвращается сама, срок берётся из подсказки CLI); там же признак «сети нет» (`network-state.json`, кулдаун 5 минут): обрыв опознаётся по тексту ошибки (только то, что не может быть ответом сервера), ставится ОДИН раз и снимается первым же ответом — иначе каждая из работ захода открывала бы отсутствие сети своим спавном `claude`.
- **Подача (хуки)**: `src/hooks/` — 9 каналов (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, Stop, PreCompact, SubagentStart, SessionEnd), зарегистрированы в `hooks/hooks.json`. PostToolUseFailure — свежее оглавление в момент упавшей правки (строки уехали → сверка со структурой дешевле перечитывания; несвежий индекс молчит). SubagentStart — срез паспорта свежему сабагенту (законы + карта модулей, порядок секций по типу агента, бюджет ~1400 симв.): форк ловится SessionStart-матчером `fork`, а свежий сабагент стартовал с чистым окном и терял паспорт ровно там, где делаются разведка и план. PreToolUse (матчер `Read`) — подача ДО чтения: то же знание об узле, что даёт PostToolUse, но в момент, когда решение ещё принимается, плюс названная вслух цена альтернативы (оглавление ≈150t против файла в тысячи). Ничего не блокирует принципиально: запрет обязывал бы нас быть правыми, а индекс отстаёт от диска — предлагается дешёвый путь, выбирает модель. Дедуп общий с остальными каналами (jit_log). Дар по касанию у обоих каналов — ОДИН код (`touch-feed.ts`): матчер PostToolUse намеренно не ловит `Read`, иначе одно чтение стоило бы два запуска процесса (замер: 83ms + 84ms) ради одного и того же текста. Стоимость канала — почти целиком старт рантайма и разбор бандла: ранний выход стоит столько же, сколько полная работа (80ms при 38ms холостого node), поэтому оптимизировать надо число запусков, а не код. SessionStart-матчер ловит `startup|resume|clear|compact|fork` — сводка переинжектится после сжатия контекста и в форк-сабагенты (иначе теряют паспорт). PreCompact — пульс + оппортунистический харвест перед сжатием (best-effort, условный канал). Протокол самостарта (`entry.ts`): при входе реконструирует состояние работы (нить прошлой сессии + незакоммиченное + недавно горячее как сид ×50) и её PPR-граф-окружение → блок «Вход в работу» (промпт — сид, а не карта). Паттерн: тонкий процесс-вход (`session-start.ts`, читает JSON из stdin) + чистое ядро (`session-start-core.ts`, тестируется без процесса). Каждый канал пишет heartbeat (`heartbeat.ts`), молчание НАДЁЖНЫХ каналов диагностируется (`diagnose.ts`; условные — PreCompact/SessionEnd/PostToolUse/PostToolUseFailure/SubagentStart — не тревожим). Телеметрия эффективности (локально): поданный файл, затем отредактированный → `jit_log.used=1` (`markUsed`), «утилизация подачи» в /sym-status (детерминированный прокси «используется ли знание», ответ на провал memory-плагинов).
- **Принуждение**: `src/gates/` — гейт формы по законам паспорта (dry-run по умолчанию, блокировка с предохранителем). `src/verifiers/` — самосозданные верификаторы направления (эмерджентно по расширению файла, как плейбуки): `content.ts` — чистота алфавита (гомоглифы кир/лат), целостность ссылок (битые внутренние, дубли/пустые анкоры); `security.ts` — страж защитных слоёв (по git-диффу: снятая валидация/аутентификация/security-заголовки/rate-limit/CSRF + внесённый риск CORS*/eval/TLS-verify-off — «ни одна правка не ослабит защиту молча», OWASP, кросс-язык, анти-шум: перемещение защиты в том же диффе не флагается). Текут в тот же гейт-поток (gate_log), dry-run/блокировка по gate.json.
- **Петля**: `src/gardener/` — поправки владельца (дифф «модель написала → человек исправил» = невыведенная конвенция), дедуп фактов в два прохода (`dedupe.ts`: SimHash берёт почти-одинаковые СТРОКИ, смысловой проход — пересказы, у которых общих слов нет вовсе, вплоть до другого языка; замер на собственном паспорте: из 31 размеченной пары лексика не поймала ни одной, поэтому судит модель, а слияние остаётся вытеснением), SimHash (`simhash.ts`: и факты, и почти-дубли кода в `clones.ts` — точные дубли по хэшу, почти-дубли по расстоянию Хэмминга с бандовой раскладкой; сгенерированное отсеивается до нормализации), авто-обучение детач-процессом, компаундинг уроков (`lessons.ts`: зона-индексированные уроки из анализа поправок → JIT-автоподтяжка при возврате в зону, «здесь владелец уже исправлял X»), слой дрейфа (`drift.ts`: снимок здоровья на коммит — конвенции/сироты/плотность графа/гейт-поимки — и дельта-дрейф в /sym-status, «производная паспорта»; исходная боль тестировщика «харнесс сам наводит беспорядок»).
- **MCP**: `src/mcp/` — deferred-сервер `passport` (9 инструментов `passport_*`: conventions/history/map/impact/related по коду + orphans/reach по контент-графу + outline/unfold по индексу структуры), зарегистрирован в `.mcp.json`.
- **Дистрибуция**: `src/bundle/` (ядро: точки входа, переписывание ссылок, хэш свежести — единый источник для сборки и селф-линта) + `scripts/bundle.ts` (процесс: bun build плоско в `plugin/dist` + wasm-поднабор слоя 1 + манифесты/скиллы на dist + смоук). Инвариант: все выходы сборки в ОДНОМ каталоге — рантайм-резолвы (`detach.ts` ищет auto-learn.js соседом, `ast.ts` ищет ../wasm) пляшут от import.meta.dir.
- **Скиллы**: `skills/*/SKILL.md` — тонкие обёртки; логика в `src/cli/` (status, map, elevate, charter, learn, export…). `/symbiont:export` — единственная запись в репозиторий владельца (маркированная секция паспорта в AGENTS.md для других агент-инструментов), всегда явной командой, никогда из хука. `src/elevate/` + `src/domains/` — аудит возвышения, доменные плейбуки и рамка легитимности (`frame.ts`: детект чувствительного проекта + сухие правдивые дисклеймеры продукта из его же контента → снижение ложных отказов; компилятор отбрасывает анти-паттерны императив/эмоция/persona; `frame.md` пишет buildPassport, инжектит SessionStart).
- **Тесты**: `tests/` — bun test, общие хелперы в `tests/_helpers.ts` (временные миры-проекты). Зона исторически хрупкая — менять осторожно, гонять полностью.

## Ключевые инварианты (нарушение = архитектурная ошибка)

- **Ноль хардкода**: в ядре нет правил про конкретный язык/фреймворк/стиль — всё выводится из проекта по сигналам. Новая конкретика — только в `signals.ts` или языковые пакеты майнера.
- **Crash-only**: единственная остановка — краш, единственный старт — восстановление. Никакой логики «на выходе», без которой теряются данные; корректность живёт в реконсиляции на SessionStart. Хуки — атомарные append-записи (SQLite WAL).
- **Fail-open и «никогда молча»**: ошибка канала не ломает сессию владельца, но и не глотается бесследно — heartbeat + честное предупреждение в сводке. Провал фоновой работы не равен отказу: планировщик назначает повтор по лестнице 5мин → 30мин → 2ч (`scheduler.ts`, `MAX_FAST_RETRIES`), затем возвращает работу на обычное расписание; отсутствие следов работы дольше недели само становится строкой в сводке (`renderGardenerSilence`).
- **Журнал фактов неприкосновенен**: истина append-only; чистить можно только эфемерные рабочие таблицы (jit_log, gate_log, session_edits и т.п.).
- **Авторство правок подтверждается, а не угадывается**: `git status` отдаёт ОБЩЕЕ рабочее дерево, а сессий в одном репозитории бывает несколько разом — эвристика «грязный + свежий mtime» приписывала чужую работу себе и через `model_state` → `corrections` фабриковала ложные «поправки владельца», из которых выводились правила в неприкосновенный журнал. Что написала ИМЕННО эта сессия, знает только PostToolUse (`session_edits`); на нём стоят `model_state`, нить сессии, страж фокуса и бюджеты качества. Гейт формы шире, но не безграничен: пока сессия в репозитории ОДНА, всё грязное дерево наше по умолчанию (правки руками и через Bash мимо PostToolUse не проходят, и требовать подтверждения значило бы молча потерять гейт на этих путях); как только рядом живёт другая сессия (`openLiveOthers`), судятся только подтверждённые свои правки — претензия к чужому незавершённому файлу зовёт модель править чужое, а в режиме блокировки не даёт закрыть ход из-за кода, которого эта сессия не писала. Покрытие не теряется: файл соседа судит гейт соседа. Пропущенные файлы называются вслух одной строкой («работа соседа»), один раз на файл.
- **Корень данных передаётся, а не выводится**: и хуки, и скиллы получают `--data ${CLAUDE_PLUGIN_DATA}`. Вывод корня из пути файла — последний фолбэк (режим `dev`), и он называет себя вслух: молчаливый развод корней однажды заставил `/sym-elevate` рассуждать о паспорте двухдневной давности. Команды снимают пару `--data <путь>` из своих аргументов через `stripDataFlag`.
- **Конвенция языка требует присутствия языка**: ось языкового пакета молчит, пока файлы её языка не набрали ни доли (`MIN_LANG_SHARE`), ни числа (`MIN_LANG_FILES`) в проекте. Наблюдения ось берёт с файлов, и плотный чужой файл перевешивает по наблюдениям весь остальной проект: шесть PHP-файлов (два из них — одноразовые пробники) дали 140 наблюдений и вышли законом «массивы — короткий синтаксис []» в паспорт Python-репозитория — рядом с отступами, намайненными со всей базы, и неотличимо от них.
- **Отсутствие называется отсутствием**: у факта с пустым классом контрпримеров основание звучит «ни одного случая обратного на N наблюдений», а не «1016 из 1016 (100%)» — иначе оно стоит в строке неотличимо от «139 из 140», где правило действительно нарушали. Формулировка там же, где остальные (`core/store.ts` `factBasis`). Отвергнуто «не показывать такие факты вовсе»: именно они кормят гейт — «var не используется» ловится чаще прочих законов и исчез бы вместе с проверкой в репозитории без единого var.
- **Непрозрачный материал не участвует в накоплении**: картинки, шрифты, медиа, архивы (`isOpaqueMaterial`, единственный список) не попадают ни в разбор непокрытого, ни в межпроектный каталог видов. У бинарного файла нет строк, и «.png: характерный размер ~169 строк» — это байты картинки, поделённые по 0x0A: число получено честно и потому выглядит статистикой. Проверка стоит и на записи, и на чтении — уже накопленное чистится первым обращением.
- **Сгенерированное не голосует о стиле**: файл со средней длиной значимой строки выше `GENERATED_LINE_CHARS` (миниф, бандл, дамп данных в синтаксисе языка) даёт НОЛЬ стилевых наблюдений — он остаётся в составе материала, но конвенций не свидетельствует. Порог один на плагин (`miner/analyze.ts`, детектор клонов берёт его же). Тот же класс, что «повтор — не подтверждение»: объём наблюдений без объёма решений автора. Найдено замером — два бандла AWS SDK (дампы JSON в PHP, 266КБ в трёх строках) переворачивали вердикт по массивам на всём WordPress.
- **Строки и комментарии вырезаются одним проходом** (`miner/packs.ts` `codeOnly`): области вложены друг в друга (`#` внутри строки, апостроф внутри комментария), поэтому любой порядок двух регэкспов ошибается — и обе ошибки наблюдались на боевом коде.
- **Измеренное и выведенное — различимы наружу**: у статистики майнера в строке стоит измеренная распространённость («5339 из 5344»), у правила от модели — «выведено по N образцам (уверенность X%, не измерено)». Формулировка живёт в ОДНОМ месте — `core/store.ts` `factBasis`; своя копия где-либо ещё запрещена и ловится селф-линтом. То же различие в профиле качества: ось, подтверждённая только текстом доков, называется заявленной, а не действующей.
- **Язык подачи — русский по умолчанию, и его определяет КАЖДАЯ точка входа**: умолчание отвечает на вопрос «что показать, когда признаков нет», и цена ошибки несимметрична — русская строка в английской сессии видна сразу, английская сводка у русскоязычного владельца выглядит замыслом. Лестница наблюдений (выбор → env → язык сообщений → комментарии → доки → локаль → коммиты) не тронута, сменилась только последняя ступень; явный выбор ставится командой `/symbiont:lang`. Каждая точка входа обязана позвать `initLang` ДО первой отрисованной строки: без этого канал говорит на умолчании процесса, а не на языке владельца — так выбор соблюдали четыре точки входа из пятнадцати, молча и одинаково у всех. Сторожит тест, берущий список входов у сборщика.
- **Язык подачи переводится на последней миле, а таблицы объявляются вслух**: в журнале формулировка русская всегда (по ней считается ключ вытеснения), английская рождается в момент показа через `statement()`. Пары регистрируются ПРИ ЗАГРУЗКЕ объявившего их модуля, поэтому точка входа, которая факты только читает, обязана импортировать `core/statements.ts` — иначе она молча заговорит по-русски в английской подаче (так разъехались разом MCP, сводка, JIT-срез и гейт). Список проверяемых точек не задан руками: кто зовёт `statement()`, тот и обязан объявить загрузку — сторожит тест.
- **Сгенерированное не судится законами, раз оно их не устанавливало**: файлы производных каталогов (`inDerivedZone` из `miner/walk.ts` — единственный список) исключены и из майнинга, и из гейта. Судить вывод сборки конвенциями значит держать его перед планкой, которую ему не дали помогать устанавливать, да ещё и без возможности исправиться: следующая сборка перезапишет. Детектор по содержимому (`looksGenerated`) здесь не работает — bun не минифицирует, средняя строка артефакта 39 символов при пороге 200.
- **Носители секретов не читаются никогда**: боевой `.env` и его варианты, ключи/сертификаты, учётки пакетных менеджеров (`isSecretCarrier` в `env/config-graph.ts` — единственный список) не открываются ни одним проходом; из образцов (`.env.example` и родня, `ENV_TEMPLATES`) берутся только имена. Значение, похожее на секрет, в обычном конфиге (`looksSecret`) в запись не попадает — ключ остаётся уликой. Уже накопленное в `config_edges`/`contract_rule` чистится первым обращением. Отвергнуто «читать и маскировать»: маска ловит похожее на секрет, а секрет не обязан быть похожим; у боевого env-файла нет ценности, которой не давал бы образец. Сообщено снаружи как утечка (v0.123.0).
- **«Готово» требует запущенной проверки**: Stop-гейт читает транскрипт сессии (`gates/evidence.ts`) и называет кодовые файлы, правленные после последней команды проверки (тесты/линтер/тайпчек — распознаются по форме команды, не по имени проекта). Ни одного нового процесса: Bash не хукается, транскрипт уже на диске. Судятся только подтверждённо свои файлы и только в проекте, где тесты есть; dry-run — наблюдение, режим блокировки — нарушение наравне с законами формы.
- **Фантомный импорт ловится на записи**: имя, импортированное из файла проекта, которого там нет (`verifiers/phantom.ts`), называется сразу в PostToolUse — по индексу структуры, детерминированно. Проверка односторонняя: только источники, которые эта сессия не писала, и только при свежем хэше; иначе молчание — ложный «фантом» дороже пропущенного.
- **Совет о дешёвом пути не работает, работает результат инструмента**: на собственном паспорте 0 из 14 предложений «есть оглавление» привели к `passport_outline`. Поэтому есть режим `outline: "deny"` в `gate.json` (`readOutlineMode`): первое чтение большого файла целиком отменяется, а причиной отказа уходит само оглавление; диапазон (offset/limit), повтор и файлы, писанные сессией, не отменяются. Режим — явный выбор владельца, по умолчанию выключен: отмена сильнее подсказки.
- **Окупаемость подачи измеряется лифтом, а не корреляцией**: «подано → файл правили» верно и тогда, когда модель шла туда сама. Каждая десятая подача удерживается (`shouldWithhold`, детерминированно по сессии и ключу) и образует контрольную группу; лифт вида = доля пользы среди поданных минус среди удержанных (`liftOf`), показывается в /sym-status при ≥8 удержаниях. `SYMBIONT_HOLDOUT=0` выключает (тесты, канарейка). Бриф узла, три сессии подряд не пригодившийся, молчит пять сессий и пробуется снова (`briefSilenced`).
- **Бюджет сводки тратится по ценности строки**: при обрезке из самой толстой секции уходит строка с наименьшей ценностью на символ, где ценность — число поимок её правила гейтом (`lineValueFromGate`). Закон, который модель соблюдает и без нас, уступает место тому, который она нарушает. Правило по-прежнему не знает названий секций.
- **Закон может действовать в одной зоне проекта**: верхний каталог с собственной выборкой (≥ `ZONE_MIN_FILES`) даёт закон, которого проект в целом не набирает (`deriveZoneFacts`); у такого факта область `area@zone`, свой ключ и своя история, в сводке — «· только в tests/». Гейт применяет его только к файлам зоны (`lawsForFile`), а срезы без файла (сабагент, экспорт, вербализация) его не показывают (`globalLaws`). Глобальный закон зонами не дублируется. Живая проверка на самом репозитории: «стрелочные функции — используются свободно · только в tests/ — 98%».
- **Длинная разведка без правки — сигнал делегирования**: `searchChurn` (тот же транскрипт, что у гейта доказательств) считает подряд идущие шаги поиска/чтения; серия рвётся правкой и новым сообщением владельца. От `CHURN_STEPS` шагов канал до чтения один раз на серию называет прочитанные файлы готовым сидом для Explore-сабагента. Совет с числами, не императив.
- **Сказанное вслух получает голос только повтором**: правило, произнесённое владельцем в чате («никогда не трогай прод-оплаты»), не попадает в код и умирает с сессией. Stop снимает из транскрипта предложения формы предписания/запрета (`gardener/voiced.ts`) — ТОЛЬКО из набранного владельцем (строка content, без isMeta, не служебная, ≤2000 символов: без этого фильтра «правилами владельца» становились строки паспорта из наших же headless-промптов, 62 сессии подряд); одиночная фраза молчит, повтор в ≥`VOICED_MIN_SESSIONS` разных сессиях показывается в сводке и в `/symbiont:charter` как кандидат в устав — не закон. Уже зафиксированное в уставе не дублируется (`sameThought`, доля общих слов). Отвергнуто хранить и искать сырые ходы транскрипта: отозванный вердикт, поданный обратно тем же каналом, выглядит авторитетно.
- **Канал подачи без замера не появляется**: `scripts/prompt-sim.ts` проверяет любой канал «промпт → файлы» на собственных транскриптах против правок той же сессии и честных бейзлайнов (случайные файлы, три хаба — последние и так в сводке). Так отклонён лексический канал по описаниям ролей модулей и по похожим прошлым промптам (память сессий): точность 2–11% против 8% у хабов и 21% у канала «названный файл/символ». FTS5 как основа тоже отвергнут: в `node:sqlite` его нет, а bun-only расширение ломает инвариант рантайма.
- **Сводка — справочные данные, не инструкции**: заголовок паспорта говорит это вслух. Строки выведены из кода и доков ЧУЖОГО проекта и цитируют их; императив, попавший в README, не должен стать инструкцией модели через нашу же подачу.
- **Плагин не реагирует сам на себя**: собственные LLM-проходы идут через headless `claude -p` — это полноценная сессия Claude Code с нашими же хуками. Все свои вызовы помечаются `SYMBIONT_INTERNAL=1` (`src/core/internal.ts`), каждый хук-вход при метке выходит мгновенно. Без этого проход из временного проекта плодит паспорта-призраки в данных владельца и жжёт токены на рекурсию.
- **Тяжёлое — только detach**: из хуков не спавнить powershell и не держать клиент ожиданием; фоновая работа — отцепленный процесс (`detached` + `stdio:ignore` + `windowsHide` + `unref`). Windows — first-class.
- **Пассивная цена ≈ 0**: сводка 2–4k символов, MCP deferred, описания скиллов короткие. Каждый постоянный токен оправдывается. Бюджет подачи тратится по ВЕСУ секций, а не по их месту в файле (`fitToBudget`): слайс по 8000-му символу безобиден, пока паспорт мал, а на зрелом проекте самая толстая секция стоит раньше измеренных и выталкивала из подачи профиль качества и карту ключевых модулей — то, ради чего сводку и читают. Режем поштучно у самой длинной секции (правило не знает ни одного названия секции — иначе сломалось бы на другом языке подачи), и урезанная секция называет, сколько строк осталось за кадром.

## Стиль кода

Код и идентификаторы — английский, комментарии — русский. Без точек с запятой, одинарные кавычки, 2 пробела, camelCase. Код почти полностью синхронный (bun:sqlite, spawnSync) — async без необходимости не вводить. Ключевые модули открываются JSDoc-заголовком с архитектурным обоснованием (не пересказом кода); у нетривиальных решений комментарием фиксируется отвергнутая альтернатива и причина. Отсутствие значения — `| null`, не optional. Проглоченная в catch ошибка сопровождается комментарием, почему молчание безопасно.
