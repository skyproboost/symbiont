# Symbiont — живой паспорт проекта для Claude Code

> Симбионт: живёт с проектом, полностью подстраивается под носителя, индивидуален для каждого.
>
> Версия 0.1 · 2026-07-29 · закрытая лицензия · владелец: skyproboost
>
> Статус: концепт, синтезированный из 6 исследований (ниша, наука, экосистема, RU-практика, механизмы Claude Code) и сессии проектирования с владельцем. Следующий шаг — прототип майнера конвенций (проверка главного риска).

---

## 1. Миссия

Плагин для Claude Code, который на **любом** проекте — новом или существующем, маленьком или большом — делает работу модели быстрее, точнее, дешевле и стабильно качественнее за счёт того, что:

1. **мгновенно ориентируется** в проекте (или создаёт его «паспорт» с нуля) — новая сессия не тратит токены на переоткрытие;
2. **подстраивается** под проект тотально и без хардкода: архитектура, идея продукта, технические/программные/семантические правила, вплоть до неписаных законов («только `var`», венгерская нотация `sType`, запрет стрелочных функций);
3. **держит стоячие цели владельца в ядре** («веду проект в топ-1 по производительности/качеству/архитектуре») — их не нужно повторять в каждом промпте;
4. **выжимает максимум** по осям качества, важным *именно этому* проекту (профиль качества выводится из концепции продукта, не из абстрактного чеклиста);
5. **не деградирует**: качество движется только вверх (храповик), система учится на каждой сессии и на каждой поправке владельца;
6. **не переписывает работающее**: сдержанность — часть ядра наравне с амбицией.

Ключевая формула: **знание — дёшево и всегда; дорогая механика — точечно и по триггеру; критичное — детерминированно, а не «по памяти модели»**.

## 2. Почему сейчас и почему так — исследовательская база

### 2.1. Ниша существует и горячая, но все лидеры больны

| Игрок | Что делает | Что сломано |
|---|---|---|
| [Graphify](https://github.com/Graphify-Labs/graphify) (~98k★, YC S26) | tree-sitter-граф кода + LLM-извлечение из доков, MCP + хук «граф прежде grep» | Хук **молча умер** при обновлении Claude Code ([#578](https://github.com/Graphify-Labs/graphify/issues/578)); Claude игнорирует граф без активного хука ([#921](https://github.com/Graphify-Labs/graphify/discussions/921)); на малых проектах выгода ≈ 1×; семантический слой протухает первым; tree-sitter без резолва типов терял до 60% связей (ObjC) |
| [claude-mem](https://github.com/thedotmack/claude-mem) (~89k★) | автозапись сессий, SQLite+Chroma, воркер | HIGH-риск: HTTP API без аутентификации ([#1251](https://github.com/thedotmack/claude-mem/issues/1251)); хроническая ломкость на Windows; **в 95.2% сессий память ни разу не запрошена** — налог платится всегда, польза редко |
| [Serena](https://github.com/oraios/serena) (~25k★) | LSP-over-MCP | На проектах <20k строк контекст кончается *быстрее*; утечки до 30GB RAM; ценность съедена нативным LSP Claude Code |
| mem0 / Zep-Graphiti / cognee / Letta | универсальные памяти-платформы | Построены под user-facing SaaS-агентов; граф-БД + LLM-вызовы на каждую запись не окупаются для «один разработчик — одна кодовая база»; бенчмарки вендоров не воспроизводятся |

### 2.2. Три системные болезни ниши (наш плагин строится от противного)

1. **Push игнорируется, pull забывается.** Пассивные инструкции модель не соблюдает, memory-инструменты не вызывает, активные хуки ломаются молча. → У нас: знание приходит само в нужный момент (SessionStart/PostToolUse), критичное — принуждается детерминированно (Stop-гейт), а поломка каналов **самодиагностируется**.
2. **Пассивный налог платится всегда, польза факультативна.** MCP-определения — до 40% окна до первого слова (замер [systima](https://systima.ai/blog/claude-code-vs-opencode-token-overhead): Claude Code и так шлёт ~33k токенов до старта). → У нас: deferred-MCP (схемы не грузятся до востребования), скилл-описания ≤1536 симв., сводка 2–4k. Пассивная цена системы — близка к нулю.
3. **Наполнение памяти — отдельный дорогой пайплайн** (cognee: 200+ LLM-вызовов на документ). → У нас: наполнение — бесплатный побочный продукт работы (PostCompact-саммари, Stop-хук, диффы поправок владельца).

### 2.3. Что доказано (факты, на которых стоит дизайн)

- **«CLAUDE.md — advisory (~80% соблюдения), хук — детерминизм (100%)»** — официальная формула Anthropic ([best practices](https://code.claude.com/docs/en/best-practices)). Всё критичное — только через детерминированные ворота.
- **Grep выигрывает one-hop, граф — multi-hop**: независимый замер [Codebase-Memory](https://arxiv.org/pdf/2603.27277) — ~10× меньше токенов на multi-hop вопросах о коде (31 репозиторий). Anthropic сознательно отказался от RAG в пользу agentic search ([Cherny](https://x.com/bcherny/status/2017824286489383315)) — и на one-hop прав.
- **Симулированный круглый стол в одном вызове сильной модели работает** ([SPP](https://arxiv.org/abs/2307.05300), [meta-prompting](https://arxiv.org/abs/2401.12954)); динамические роли под задачу > фиксированный пантеон. Боевое подтверждение владельца: круглый стол в thinking — ядро LabReadAI.
- **Дебаты реальных агентов в среднем не окупаются**: при равном бюджете проигрывают самокоррекции ([Cost of Consensus](https://arxiv.org/html/2605.00914v1)); за ~3 раунда — эхо-камера; голосование выбрасывает правильные ответы (oracle gap до 32%). Собственный A/B владельца: ничья при 4× цене.
- **Персона ≠ точность**: «шапка эксперта» не улучшает ответы (3 независимых исследования: [162 роли](https://arxiv.org/abs/2311.10054), [Wharton](https://gail.wharton.upenn.edu/research-and-insights/playing-pretend-expert-personas/), [PRISM](https://arxiv.org/html/2603.18507v1)), внедоменная — вредит. Роль = **линза + чек-лист + стратегия поиска**, не биография.
- **Разнообразие > клоны**: 2 разнородных агента ≥ 16 одинаковых ([Agent Scaling via Diversity](https://arxiv.org/html/2602.03794v1)); панель из 3 разных дешёвых судей точнее одного дорогого ([PoLL](https://arxiv.org/html/2404.18796v1)).
- **Мультиагентность = 15× токенов** и оправдана только когда задача параллелится на чтение и дорога ([Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system)); **писатель — один**, агенты добавляют чтение/ревью ([Cognition](https://cognition.com/blog/dont-build-multi-agents)).
- **Verification is the bottleneck** — тема 2026. Лучший анти-шум для ревью: confidence-score 0–100 с порогом 80 + явные исключения (официальный `/code-review`). «Ревьюер, обязанный найти проблемы, найдёт их и в здоровом коде» — принудительный минимум находок запрещён.
- **Зоопарк агентов вреден**: 100+ перекрывающихся описаний ломают делегирование; острый набор ~10 надёжнее ([опыт «100 субагентов»](https://dev.to/suraj_khaitan_f893c243958/i-built-100-claude-code-subagents-these-are-the-12-that-actually-earn-their-context-10nn)).
- **Память протухает**: auto-memory со старыми общими правилами уводит сессии не туда; HANDOFF-паттерн «что оказалось тупиком» подтверждён трижды независимо (tw93, Хабр, Anthropic NOTES.md).
- **Компаундинг работает**: «каждая единица работы делает следующие легче» — пост-задачный урок в структурированный файл + автоподтяжка ([compound-engineering](https://github.com/EveryInc/compound-engineering-plugin)); официальный hookify умеет генерить правила **из анализа сессии** («за что меня исправляли»).

## 3. Аксиомы дизайна

1. **Ноль хардкода.** В ядре нет ни одного правила про конкретный язык, стиль или фреймворк — только цикл *наблюдай → выводи → подавай фактами → компилируй в ворота → учись на поправках*. Вся конкретика добывается из проекта. В ядре нет и заранее заданного списка «направлений»: фронтенд, БД, кроны, дизайн-процесс, деплой не перечислены в коде — направления **обнаруживаются** по сигналам содержимого, включая те, которых мы не предвидели.
2. **Детерминизм для критичного.** Всё, что должно случаться всегда, — хук/гейт (100%), а не инструкция (~80%).
3. **Факты, не императивы.** «В этом репо 4800 функций, стрелочных — 0» работает лучше «ВСЕГДА используй var» (и не триггерит anti-injection; императивы и persona-нажим повышают отказы — подтверждено и исследованиями, и боевым опытом LabReadAI).
4. **Пассивная цена ≈ 0.** Каждый токен постоянного присутствия оправдывается; всё тяжёлое — по требованию (deferred/JIT/progressive disclosure).
5. **Наполнение — побочный продукт.** Никаких отдельных дорогих пайплайнов индексации знаний из сессий.
6. **Писатель один.** Агенты умножают чтение, ревью и независимость взглядов — не письмо.
7. **Дорогое — по триггеру.** Панели, глубокие проходы, переиндексация — только по признакам (high-stakes, «дрожащий» ответ, крупный дифф), никогда «на всём».
8. **Храповик.** Гейты не дают регрессировать по осям профиля качества; уроки не теряются; память ревизуется (протухшее удаляется, у фактов есть срок годности).
9. **Сдержанность в ядре.** Пары «цель + ограничение»: стремись к топ-1, но улучшения сверх задачи — предлагай, не делай. Если дифф описывается одним предложением — без церемоний.
10. **Живучесть важнее фич.** Слоистая деградация, самодиагностика, минимум предпосылок к окружению. Плагин никогда не падает в ноль и никогда не ломается молча.

### 4.1. Паспорт — «что-то», которое формируется для проекта

Все артефакты — читаемые файлы (MD/JSON) в `.claude/` проекта и `${CLAUDE_PLUGIN_DATA}`. Отлаживаемо глазами, версионируемо, переносимо.

**Карта проекта — зум-граф (LOD).** Компактная (в духе aider repo-map: ужата в бюджет, а не «вся правда»): структура, входные точки, ключевые модули, граф зависимостей для multi-hop вопросов («что сломается, если менять X»). Строится детерминированно (слой 0 + слой 1, см. майнер). У каждой точки — **зум-уровни, как у онлайн-карт**: z0 — одна строка («модуль оплат, Tinkoff, 12 файлов»), z1 — абзац (роль, связи, конвенции зоны), z2 — полные факты/прецеденты/«why», z3 — сам код. Обход — бюджетный и адаптивный: релевантность задачи (персонализированный PageRank от сида — затронутых файлов и текста промпта) решает, где агент спускается до z2–z3, а где проходит по z0; «задача про SEO → глубоко в структуру страниц/sitemap/OG, по остальному — поверхностно». **Глубина — функция близости к задаче, а не настройка.** Математика слоя — четыре проверенных дешёвых алгоритма, отлаживаемых глазами: персонализированный PageRank (ранжирование под задачу, боевой паттерн aider), кластеризация Leiden (смысловые «планеты»-сообщества, как у Graphify), best-first обход под токен-бюджет, байесовское обновление + decay в петле фактов. Экзотика (эмбеддинги, бустинги, тензорные представления) отвергнута осознанно: на нашем масштабе не даёт ничего сверх этого набора, но убивает отлаживаемость.

Резюме z-уровней — **ленивые** (главный урок LazyGraphRAG: Microsoft сжёг десятки тысяч долларов на upfront-LLM-индексации GraphRAG и сам её дезавуировал): резюме узла рождается при первом визите, кэшируется, инвалидируется пересборкой. При поиске узлы всех z-уровней конкурируют в **одном** ранжировании (collapsed-tree, урок RAPTOR), а не строгим спуском сверху. Поверх статической важности — «**тепло**» (influence maps из геймдева): недавно тронутые файлы излучают релевантность по рёбрам с затуханием на 2–3 хопа и остывают между сессиями; итог = статическая важность × динамическое тепло. Идентичность узла переживает переименования через patience-якоря диффа (сматчить уникальные якорные строки старой и новой версии) — факты и рейтинги не теряются при переносе кода.

**Конвенции формы.** Выведенные неписаные законы с **уверенностью из распространённости** («0 из 4800» — закон; «12 из 4800» — привычка с исключениями). Три слоя добычи:
- *Слой 0 — универсальный, любой язык*: статистика файлов/строк, регулярки по идентификаторам (венгерская нотация выводится без AST), отступы, структура каталогов, git-история.
- *Слой 1 — AST* (tree-sitter WASM, ~40 языков, докачка грамматик лениво): доли конструкций (стрелочные, var/let/const, деструктуризация в параметрах), паттерны обработки ошибок.
- *Слой 2 — LLM-вербализация* по репрезентативной выборке: правила, не выводимые статистикой («ошибки возвращаются, а не бросаются»). Один проход, дорогой, по явной команде.

Устройство слоя 0: **универсальное ядро + языковые пакеты**. Ядро (walker, отступы, структура, именование файлов, git-история) работает на любом проекте — включая репозиторий вообще без кода (контент, дизайн-ассеты). Языковые пакеты (JS: var/стрелочные/венгерская; Python: snake_case/аннотации; и т.д.) — подключаемые наборы чистых функций по одному шаблону; какие активировать — решается по обнаруженным расширениям. Слой 1 покрывает ~40 языков одним механизмом tree-sitter.

**Граница среды** (честная): мир Claude Code — файлы проекта + CLI + API. Артефакт-файл (.pptx = zip XML со шрифтами и структурой; .psd-метаданные; конфиги, экспорты, ассеты) — полностью майнится. Программа с API (Figma, Wordstat) — направление с плейбуком. Работа *внутри* GUI-программы (двигать слои в Photoshop) — за пределами платформы Claude Code, и это граница платформы, не Symbiont.

**Направления (domains).** Обнаруживаются сигналами содержимого, не зашиты: файлы миграций/схем → «проектирование БД»; компоненты + стили → «UI»; планировщики → «фоновые задачи»; Figma-ссылки в доках → «дизайн-процесс»; Dockerfile/CI → «деплой» — и так далее для любого направления. Каждое обнаруженное направление получает свои прецеденты, свои оси в профиле качества и свою роль за столом — и ещё три вещи, дающие эффект «проактивной компетентности» (то самое «магическое»: система сама понимает, что затронуто, и сама делает как эксперт):

- **Плейбук** — выведенный из проекта процесс «как здесь делается работа этого направления», включая **инструменты, найденные в самом репо** (скрипты, пайплайны): «новая статья = ядро из Wordstat через ws-core → текст → перелинковка → OG → sitemap → аудит». Шаги вроде «сходить за ключами» записаны в плейбуке — их не нужно проговаривать в промпте. Автономия с внешним миром/деньгами — по правилам конституции (бесплатное по ключам проекта — сам; платное/публикация — подтверждение).
- **Доменные сущности как узлы графа.** Граф — не только код: статьи, хабы, YAML-сущности, FAQ, маркеры — точки; перелинковки — рёбра. «Каскадно-транзитивная перелинковка» из магии становится графовой задачей с точным ответом: достижимость из любого хаба, сироты, дубли анкоров, глубина, распределение обратных ссылок — считается детерминированно, а не «модель постаралась».
- **Самосозданный верификатор** — система выводит/пишет чекеры качества направления и ставит их гейтом (чистота алфавита без микса кириллицы/латиницы, битые ссылки, дубли, форматные пороги). Прототип паттерна — ручной путь владельца в LabReadAI: audit-content.mjs, check-links, purifyScript/foreignWordLeak, ws-core строились по одному после боли; Symbiont делает это возникновение автоматическим для любого направления любого проекта.

Активация направления подчиняется зум-графу: касание поверхностное → z0, направление молчит; касание глубокое (пишется статья) → z3, плейбук активируется целиком. «Топ-1 в каждом направлении» достигается не энциклопедией best practices в ядре (их знает сама модель), а тем, что паспорт (а) фиксирует, как направление устроено *здесь*, и (б) гарантирует, что при касании направления модель получает его контекст, его линзу и его планку — например, при касании схемы БД в работу включается линза data-modeling с требованием топ-уровня структуры/индексов, откалиброванным под нагрузку и концепцию этого продукта.

**Архитектурные прецеденты.** Как в этом проекте делается типовая работа — из git-истории последних N фич: «новая фича = роут + сервис + миграция + тест, вот шаблон из 12 прецедентов». Модель не изобретает структуру — она следует прецеденту. Прецеденты — не только про бэкенд: для UI паспорт держит **канон компонентов** — эталонная модалка, форма, карточка со своими правилами закрытия, отступами, типографикой, breakpoints («нужна модалка → клонируй эталон X», а не «сделай новую с другими лайнхейтами»); дизайн-токены; **матрица платформ** — браузеры, мобильные, сеть/железо/ОС клиентов, выведенные из кода, доков и багфикс-истории (в git-истории видно, под что реально чинили: in-app WebView без DOM-storage, слабые устройства и т.п.). Касание UI-файла → PostToolUse подкладывает канон зоны автоматически — владельцу больше не нужно каждый раз писать «найди модалку и изучи её». (Боевое подтверждение из практики владельца: «НЕ изобретать CSS, клонировать эталон» — урок, оплаченный переделками.)

**Профиль качества.** Что значит «топ-1» *для этого продукта*: из концепции (README, доки), из кода (что измеряется, что логируется, где стоят проверки) выводится иерархия осей — скорость/SEO для лендинга, точность/приватность для медицинского сервиса, поддерживаемость для админки, совместимость/платформенность (кроссбраузерность, слабые устройства, медленная сеть) там, где аудитория этого требует.

Оси и условия профиля **каскадируются** по зум-графу, как CSS по DOM: заданное на корне («супер-производительность») действует на каждую точку вплоть до строки кода, пока не переопределено локально («этот модуль — legacy, только не сломать»); конфликты решает специфичность (более локальное побеждает). Так «топ-1 в каждой части» применяется без перечисления частей, а агент, спускаясь в зону, автоматически получает её *эффективный набор условий* (корневые + локальные).

Особый случай — **безопасность**: единственная ось, присутствующая в профиле всегда, независимо от типа проекта; но её *содержание* полностью индивидуально и выводится из обнаруженной поверхности: для веб-продукта — CSP/заголовки/валидация/nginx/анти-абуз/квоты, для CLI или библиотеки — совсем другой набор, для не-веба — третий. Паспорт фиксирует существующие защитные слои проекта, и их неприкосновенность — **гейт**: ни одна правка не может молча ослабить защиту (снять заголовок, расширить CORS, обойти валидацию) — такое либо блокируется, либо требует явного подтверждения владельца. Security-линза включается автоматически при касании любой чувствительной поверхности. Каждая главная ось получает **измеримый бюджет** (размер бандла, время запроса, покрытие) → уходит в гейты.

**Рамка контекста (анти-ложные-отказы).** Обобщение боевого паттерна владельца (CONTEXT-слой LabReadAI, снявший ложные отказы на тяжёлом медицинском контенте, ретест 3/3): для проектов с чувствительными поверхностями (медицина, собственная безопасность продукта, финансы, harm-reduction — обнаруживаются как направления, не перечислены в ядре) паспорт держит **сгенерированный факт-блок легитимности**. Основа знания: отбивает классификатор поверх модели (`stop_reason: refusal`), чувствительные темы — soft-block с оценкой контекста; снижают ложные отказы **сухие правдивые факты** (кто пользователи, добровольность/согласие, что сервис принципиально НЕ делает); повышают — мольбы, эмоциональное давление, persona-нажим (XSTest, OR-Bench, arXiv 2509.08075); вывод рассуждений наружу — тоже триггер (стол держать в thinking). Механика: (1) детект чувствительных зон при ините; (2) интервью владельца как источник **только правдивых** фактов — рамка из выдумки недопустима этически и хрупка практически; (3) компилятор рамки структурно запрещает анти-паттерны (императивы/эмоции/персоны); (4) подача по каскаду и зуму: несенситивному проекту — ноль токенов, чувствительная зона → рамка инжектится при касании — в сводку, в **каждый сабагент** (они теряют контекст родителя) и в каждый LLM-вызов самого плагина по этому контенту; (5) **петля закалки об отказы**: ложный отказ на легитимной задаче — измеримое событие → урожай → усиление рамки конкретными фактами → авто-ретест (паттерн стенда fable-context-retest, автоматизированный), Glicko-оценка «какие факты реально снимают отказы».

**Конституция.** Стоячие цели владельца парами «цель + ограничение». Задаётся владельцем при инициализации (интервью-паттерн: AskUserQuestion → фиксация), дальше живёт в паспорте. Инжектится в каждую сессию **и в каждый сабагент** (SubagentStart — сабагенты не наследуют память родителя, это дыра нативного стека, которую мы закрываем).

**Роли стола.** Сгенерированные из профиля качества «люди проекта»: у каждого — линза, чек-лист, стратегия поиска, привязка к осям профиля. Материал, не процесс (см. §5). Хранятся как текст, стоят ноль.

**Новый проект**: добывать нечего → конституция и выбранный стиль *назначаются* (интервью) и охраняются той же машинерией с первого коммита. Паспорт растёт вместе с проектом.

### 4.2. Машина подачи — дирижёр контекста

| Канал | Когда | Что даёт | Цена |
|---|---|---|---|
| SessionStart-хук | старт/resume/clear/compact | сводка паспорта 2–4k симв.: карта-выжимка, топ-конвенции, конституция, статус (git, незакрытые нити из handoff) | одна инъекция |
| UserPromptSubmit-хук | каждый промпт | JIT-ретаргетинг: по тексту промпта — релевантный срез паспорта (конвенции зоны, прецедент задачи, роли), дешёвой эвристикой/haiku | только релевантное |
| PostToolUse-хук | чтение/правка файла | конвенции и связи *этого* файла («узел X, callers: Y,Z»); генерируемые path-scoped rules в `.claude/rules/` Claude Code грузит сам | по месту |
| MCP-сервер (deferred) | по запросу модели | multi-hop вопросы: `impact_of`, `find_precedent`, `why_decision`, `graph_query` | ≈0 пассивно |
| Скилл `user-invocable: false` | модель сама | детальный срез паспорта через `` !`cmd` `` — всегда свежий | описание ≤1536 симв. |

**Протокол самостарта.** Промпт пользователя — сид, а не карта. «Продолжи вчерашний файл» не исполняется дословно-вслепую: под капотом система восстанавливает состояние (HANDOFF, git-дифф, незакрытые нити, релевантный срез зум-графа), реконструирует *намерение* и формирует план входа. Если план пользователя хорош — распознать и идти по нему; если нет — сделать, что просили, но подложив правильную подготовку. Стартуем с полного понимания, а не со слов.

**Пейджинг контекста (RAM/диск)** — политика «держать фокус, ничего не терять»: контекст сессии = оперативка (только горячее), паспорт/журнал = диск (всё остальное, семантически ужатое, адресуемое), возврат = page fault через deferred-MCP («найдём и переосмыслим»). Механика: (1) всё ценное журналируется **до** любого сжатия (инкрементальный урожай) — платформенное выселение tool-результатов (микрокомпакт) становится безопасным; (2) compact-инструкции заменяют содержимое **указателями** на узлы паспорта: z0-строка с адресом («решения по оплатам → журнал #47, поднять passport_query») — 20 токенов вместо 2000, но ничего не потеряно; (3) кодирование только **семантическое** (z-уровни, структурные факты, указатели) — бинарное/архивное сжатие в контексте отвергнуто: модель читает текст, блоб для неё мусор. Родословная: MemGPT/Letta (иерархия память-как-ОС), ReadAgent (gist+lookup, эффективный контекст ×3.5–20), собственный HANDOFF-паттерн.

Нотация проекций — **плотные самоописанные структуры** (идея владельца «кодированные карты/таблицы»): легенда объявляется один раз в шапке, дальше — плотные строки: `оплаты[12ф] → телеметрия, БД · jsonb:только-sql.json` (~15 токенов) вместо прозы (~40); таблицы фактов — TSV-стиль, карта — adjacency-строки, код — сигнатуры вместо тел. Граница: непрозрачный шифр (аббревиатуры без легенды, base64) отвергнут — модель начинает гадать, точность падает; плотность не должна стоить понимания.

**Lifecycle контекста** (то, чем не управляет никто из конкурентов):
- **PreCompact**: перехват auto-compact в плохой момент — сначала выгрузка знаний сессии, затем компакция; compact-инструкции паспорта диктуют, что переживает сжатие (архитектурные решения и «why» — никогда не суммаризировать; tool output — выкидывать).
- **PostCompact**: `compact_summary` — бесплатный урожай в петлю самообучения.
- **Stop-хук на границе задачи**: генерация **HANDOFF** («сделано / пробовали / **тупики** / следующий шаг») + факт-подсказка: «задача закрыта, контекст X%, чистый момент для /clear — конспект сохранён».
- Дисциплина из подтверждённых практик — фактами, в нужный момент: >2 неудачных правок подряд → «чистая сессия с лучшим промптом бьёт третью заплатку» (совпадает с правилом №1 владельца: 3 фикса = стоп).

### 4.3. Машина принуждения

- **Гейты формы**: конвенции с уверенностью «закон» компилируются в ast-grep-правила (+regex-фолбэк) → PostToolUse/Stop прогоняет по диффу → **exit 2 со списком нарушений**: модель физически не может закончить ход с нарушением. Знание, скомпилированное в гейт, не дрейфует к training prior.
- **Бюджеты профиля**: измеримые пороги главных осей качества в Stop-гейте — регрессия не выпускается. Храповик буквально.
- **Ворота выхода**: паттерн ralph-loop — completion-promise + лимит итераций (+официальный предохранитель: гейт снимается после 8 блокировок подряд — защита от вечного цикла).
- **Ревью по требованию/триггеру**: параллельные агенты с **разными мандатами** (комплаенс паспорту; очевидные баги; silent-failure-hunter; git-blame-контекст), каждая находка — confidence 0–100, порог 80, явные исключения шума (pre-existing, педантизм, «ловит линтер»). Без принудительного минимума находок.
- **Страж фокуса**: agent-хендлер Stop-хука (мини-агент Read/Grep) — «не разъехались с задачей? не начался непрошеный рефакторинг? конституция не нарушена?» → заворачивает ход.

### 4.4. Петля самообучения

- **Компаундинг уроков**: после задачи — урок в структурированный файл (`solutions/`), автоподтяжка в будущие планы (JIT, не целиком).
- **Поправки владельца — главный сигнал**: FileChanged видит ручную правку кода модели → дифф «модель написала → человек исправил» = невыведенная конвенция → кандидат в паспорт (hookify-паттерн: правило из анализа сессии).
- **Поимки гейтов** усиливают подачу правила (чаще нарушается → выше в сводке).
- **Ревизия памяти**: у фактов — срок годности и счётчик подтверждений; протухшее и неиспользуемое удаляется (ответ на подтверждённое «auto-memory протухает и уводит сессии не туда»). Автоматизация, которой перестали пользоваться, удаляется (правило Ронахера).
- **«Садовник» — единая подсистема гигиены знания** (исполнитель решений петли). Модель — поколенческий GC: mark = использование фактов из урожая, sweep = проход садовника; молодые факты проверяются часто, старые стабильные — редко (расписание даёт FSRS бесплатно). Работы: перепроверка due-фактов **дешёвым ре-майнингом якорной зоны** (детерминированно, без LLM — это и есть «переобучение»); похороны мёртвого (frecency-порог) с причиной в журнал; ре-якорение повисших якорей; SimHash-дедуп; LSM-компакция журнала (вытесненное старше N месяцев — в архив, рабочая БД маленькая). Планирование — crash-only, без демонов: оппортунистические детач-проходы (Stop/SessionEnd; разовый на SessionStart, если давно не бегал), бюджет секунд, идемпотентность, никаких молчаливых действий. Честная граница: живой контекст текущей сессии плагин чистить не может (хуки добавляют, не изымают) — там рычаги дирижёра: не сорить самому, рулить компакцией, подсказывать /clear фактами.
- **Оценка фактов — Glicko-подобная пара** (идея владельца): у факта не одно число уверенности, а два — **рейтинг** (насколько правило сильно) и **отклонение** (насколько мы уверены в самой оценке). Каждая подача/подтверждение/нарушение — «партия», обновляющая оба; **бездействие растит отклонение** (факт, давно не подтверждавшийся, становится сомнительным сам по себе — это и есть старение, без отдельного механизма); отклонение растёт и от правок соседнего кода (git трогает соседей якоря = «время для факта идёт быстрее»). Порог компиляции в гейт требует и высокого рейтинга, и низкого отклонения: «сильное правило, в котором мы уверены». Полную машинерию Glicko-2 (volatility σ — итеративный солвер, главный источник багов чужих реализаций) не берём — только пару чисел.
- **Расписание перепроверок — FSRS** (современный алгоритм интервального повторения, дефолт Anki, обкатан на 500M+ повторений; найден дважды независимо): у факта — стабильность и извлекаемость; подтверждение в работе = успешное повторение (интервал до следующей верификации растёт), поправка владельца = провал (факт уходит в частые проверки). Разделение труда: Glicko отвечает «насколько верим», FSRS — «**когда** дёшево перепроверить, пока не протух».
- **Живость — frecency** (Firefox Awesomebar, 18 лет продакшена в SQLite): частота × свежесть с half-life и порогом смерти (score < 0.1 + 90 дней без использования); механика распада — **forward decay** (нормализация одним делением при чтении, никаких фоновых пересчётов — совместимо с «ноль демонов»).
- **Дедуп новорождённых фактов — SimHash + Union-Find**: 64-битный отпечаток на факт; почти-дубли (≤3 бита разницы) сливаются в канонический факт до записи — ответ на «isValidUuid/validateUuid/checkUuid → агент пишет четвёртую копию».
- **Хранение — модель Datomic**: факт никогда не UPDATE-ится — retraction + новый факт со ссылкой `superseded_by`; журнал событий неистребим → бесплатный time-travel («что паспорт знал месяц назад») и аудит петли. Диффы правок владельца снимаются histogram-алгоритмом (`git diff --histogram`) — семантически чистые события, меньше ложных фактов из шумных диффов.

## 5. Круглый стол

Три формы, которые нельзя путать (цена различается на порядок):

1. **Симулированный стол** (дефолт): роли из паспорта инжектятся в промпт, спор живёт в thinking одной сильной модели, наружу — структурный объект. Цена ≈ 0 сверх вызова. Боевой паттерн владельца (LabReadAI) + научное подтверждение (SPP, meta-prompting; эффект есть именно у фронтир-моделей).
2. **Реальная панель** (эскалация по триггерам): отдельные вызовы, раздельные контексты. Триггеры — все, иначе не спавнить:
   - высокая цена ошибки (прод, миграции, безопасность, деньги) **и** решение реально изменится от независимых взглядов;
   - и/или дифф/чтение не влезает в один контекст;
   - и/или ответ «дрожит» (низкая уверенность, противоречия в самокритике — паттерн iMAD, −92% токенов дебатов);
   - есть объективный верификатор (тесты/запуск/typecheck) — панель без верификации = генератор уверенного шума.
3. **Персистентные роли** — материал паспорта, питающий обе формы. Роль = линза + чек-лист + стратегия поиска. Не биография, не личность, не «сеньор с 20-летним опытом».

**Протокол панели** (анти-groupthink, из доказанного): 3–5 агентов максимум, разные мандаты; **слепые вердикты** до обмена; ≤2 раундов; смена позиции без новой улики — флаг; единогласие — не успех, а красный флаг; вес у проверенных улик, не у уверенности тона; финальная верификация каждого критичного finding против кода. Писатель остаётся один.

## Команды и обсерватория («пульт наблюдателя»)

Философия: команд — минимум, потому что работа автономна (хуки); команды существуют только там, где человек **наблюдает** или проводит **границу жизненного цикла**. Данные исследований: библиотеки слэш-команд умерли как класс (awesome-claude-code выпилил категории), «большинство команд не прижилось» (Ронахер), зоопарк сущностей ломает делегирование. Правило гигиены — в ядре: команда, которой не пользуются, — кандидат на удаление.

- **`/sym init`** — рождение: майнинг (слои 0–1) → интервью владельца (конституция, рамка контекста, профиль) → паспорт + гейты + роли. Идемпотентна: повторный запуск дообогащает.
- **`/sym rebuild`** — пересборка всех проекций из журнала истины (лечит любую порчу, дёшево — Salsa делает её почти бесплатной); `--hard` — полный сброс и переинициализация с подтверждением (журнал архивируется, не стирается).
- **`/sym status`** — здоровье + дневник жизни: heartbeat каналов (что работает / что деградировало), петля за период (фактов родилось / подтвердилось / умерло), топ нарушаемых правил, tokens-to-done тренд, свежесть паспорта.
- **`/sym map`** — «звёздное небо» проекта в консоли: созвездия = Leiden-кластеры с подписями, яркость звезды = PageRank (`✦ ● ✧ ·`), туманности = направления, ANSI-цвет = тепло недавней активности, braille-канвас (2×4 точки/символ) вмещает тысячи узлов. Карта подчиняется зуму: `/sym map` = z0 (созвездия), `/sym map <зона>` = спуск в кластер (рёбра топ-N, имена узлов). Опционально `--html` — статический локальный graph.html с полным интерактивом (файл, без сервера).

```
  Symbiont · labreadai-v2 · z0                        47 сессий · 312 фактов

        оплаты ✦                    ✧ · статьи (412)
      ● ·  · ✦ Tinkoff          · ✧ · · хабы ✧ ·
        · телеметрия ·        ·  перелинковка  ·
                 \                  /
        разборы ✦ ● ✦ ————— промпты ✦ ✦ ●
      · триаж ·  imagingCore ✦   рамка CONTEXT ·
```

Всё остальное командами не становится: запросы к графу — MCP-инструменты модели; знание приходит хуками само.

## 6. Токен-экономика

Целевой бюджет пассивного присутствия системы: **≤3k токенов/сессию** (сводка + описания скиллов). Для сравнения: голый Claude Code шлёт ~33k до первого слова; 5 MCP-серверов у обычного пользователя съедают 40% окна; claude-mem в ранних версиях — до 42k/сессию.

Где система *зарабатывает* токены (по подтверждённым механизмам):
- нет переоткрытия проекта каждую сессию (сводка вместо изучения);
- нет повторных ошибок и переделок (гейты + уроки);
- multi-hop вопросы через паспорт-MCP вместо каскада чтения файлов (до ~10× на таких задачах);
- меньше мусора в контексте: подсказки lifecycle (/clear на границе, handoff, фильтрация выводов);
- роутинг: дешёвые модели на форк-задачах (`context: fork` + `model: haiku` для выжимок), сильная — на письмо;
- **модельная адаптация** (идея владельца): доступность моделей у аккаунта не предполагается, а **пробуется**: собственные LLM-вызовы плагина (вербализация, z-резюме, суждения садовника) идут по фолбэк-цепочке (сильная → средняя → дешёвая) с кэшем результата пробы; auth/billing-ошибки (StopFailure-события) инвалидируют кэш — смена аккаунта с урезанным доступом = автоматическая деградация на доступный тир, никогда не отказ. Внутри сессии — inherit по умолчанию (модель выбирает пользователь), явный тир — только для дешёвых форк-задач. Слоистая деградация распространяется и на модели;
- стол по умолчанию симулированный (1× вместо 4–15×), панель — по триггеру.

**Экономика меряется задачей, а не вызовом.** Пугающий разовый расход (10 агентов × 5 минут = 200k токенов) может быть дешевле незаметного капельного (полчаса докручивания багов = 500k + отравленный контекст): по замеру Anthropic ~80% дисперсии качества объясняется именно потраченными токенами, а «правка поверх правки» — подтверждённый главный тихий пожиратель. Поэтому система считает и показывает **токены до готового** (tokens-to-done) на задачу, а не токены на вызов, и решение «бёрст параллельных агентов vs капля» принимается по этим данным, а не по страху перед большой разовой цифрой. Это отдельное измерение Этапа 1.

## 7. Стек и живучесть

**Принцип: минимум обязательных предпосылок, ноль постоянных процессов.**

- **Ядро**: TypeScript, собранный в плоский JS-артефакт (ноль node_modules у пользователя). **Рантайм — любой из двух**: node (его зовут манифесты поставки; нужен 22.13+ ради встроенного `node:sqlite`) или bun, если он на машине есть. Знание о драйвере хранилища заперто в `src/core/db.ts` + `src/core/runtime.ts`, остальные шестьдесят модулей рантайма не видят; паритет драйверов проверяется тестом, гоняющим один сценарий обоими. Отвергнуто: `bun build --compile` даёт самодостаточный бинарник, но 50–90МБ на платформу против 27МБ артефакта — цена независимости выше выигрыша, пока node есть у всех, кто вообще запустил Claude Code.
- **Никаких демонов/портов**: всё событийное — просыпается от хука, работает, умирает. Состояние в файлах. (Уроки claude-mem: порт 37777, сироты-процессы, Windows-боль — исключены как класс.)
- **Никакой нативной компиляции у пользователя**: tree-sitter — только WASM; ast-grep — предсобранные бинарники, опционален (деградация в regex-гейты).
- **Хранилище**: читаемые MD/JSON + встроенный `node:sqlite` для индекса. Никаких векторных БД и эмбеддингов.
- **Хуки — exec-форма** (без шелла): PowerShell/bash/zsh не участвуют. Пути — только через `${CLAUDE_PLUGIN_ROOT}`/`${CLAUDE_PLUGIN_DATA}`/`${CLAUDE_PROJECT_DIR}`.
- **Слоистая деградация**: сломались PreToolUse-матчеры → работает SessionStart → сломались хуки → работают скиллы → в худшем случае остаётся статический паспорт в `.claude/rules/`, который Claude Code грузит сам. Никогда в ноль.
- **Самодиагностика**: каждый канал пишет heartbeat; SessionStart сверяет («PostToolUse молчит 3 сессии») → честное сообщение + автоспуск на ступень ниже. Урок Graphify: грех не поломка, а молчание.
- **Feature detection, не version pinning**: матрица «версия CC → возможности» — обновляемые данные, не код. Канарейка в CI: ежедневный прогон против свежего Claude Code.
- **Windows — first-class с первого дня** (владелец на Windows; половина issues конкурентов — «на Windows не работает»).

**Отказоустойчивость среды** (403, logout, смена аккаунта, сеть, VPN, железо):
- **Паспорт не привязан ни к чему внешнему**: аккаунт Anthropic, сессия, сеть, VPN — безразличны; всё состояние — локальные файлы проекта. Смена аккаунта/перелогин = новая сессия просто читает паспорт с диска, непрерывность полная.
- **Оффлайн-полнота ядра**: всё детерминированное (майнер, граф, гейты, проекции, поиск, ранжирование) работает без сети вообще. Сеть нужна только LLM-шагам и внешним инструментам плейбуков — при недоступности они помечаются «отложено» и доделываются позже, не валя остальное (слоистая деградация).
- **Crash-устойчивость**: append-only журнал + SQLite WAL — обрыв процесса/питания не портит записанное; повреждённая проекция пересобирается из истины; бэкап всего знания = копия одного файла журнала.
- **Инкрементальный урожай сессии**: чекпоинты знаний пишутся по ходу работы (PostToolUse, каждые N событий), Stop лишь финализирует HANDOFF — жёсткий обрыв посреди хода (403, kill, падение сети) теряет минуты, а не сессию.

**Смерть сессии — архитектура crash-only** (Candea & Fox; исследование путей смерти Claude Code 2026-07-29). Факты, на которых стоит дизайн: SessionEnd — best-effort с бюджетом 1.5с, НЕ срабатывает при SIGTERM/SIGHUP/kill/закрытии IDE/shutdown (регрессию Ctrl-C Anthropic закрыл «not planned» — гарантированный teardown не является обязательством платформы); **Stop не срабатывает при прерывании пользователем** (Esc/Ctrl-C во время ответа — официально); смерти хода от API (403/429/сеть/биллинг) — отдельное событие **StopFailure** (слушать наряду со Stop); Windows и Unix противоположны (консоль Windows мгновенно убивает дерево; Unix-claude игнорирует SIGHUP и зомбирует); транскрипты .jsonl бывают битыми штатно. Следствия:

- **Единственная остановка — краш, единственный старт — восстановление.** Никакой логики «на выходе», без которой теряются данные; SessionEnd — лишь ускоритель финализации, корректность живёт в реконсиляции на SessionStart.
- **Каждый хук — атомарная append-запись** (SQLite WAL `synchronous=NORMAL` — целостность при power loss гарантирована; журнал не зависит от живости чего бы то ни было). Урок claude-mem от противного: их корректность требовала живого демона и молчала при его смерти.
- **Реконсиляция на старте**: журнал сессии открывается маркером `session_open{pid, start_time}` и закрывается `session_close`; на SessionStart грязные журналы (PID мёртв или start-time не совпадает — защита от реюза PID на Windows) → «died dirty» → дожать урожай из транскрипта по курсору (идемпотентно: курсор двигается только после успешной обработки — паттерн cc-sidecar владельца). Сам SessionStart делает только дешёвую проверку и детачит восстановление в фон (на Windows тяжёлый SessionStart исторически вешал CLI).
- **Парсер транскриптов — построчный fail-open**: битые/пустые/неожиданные строки пропускаются; истина — файлы `~/.claude/projects/*/*.jsonl`, а не UI-индексы (VS Code теряет сессии из своего индекса при целых файлах).
- **Тяжёлое в SessionEnd — только detach** (отцепленный процесс с новой process group, сам пишущий через журнал — его тоже могут убить).
- **Никогда fail-silent**: хранилище недоступно → запись во fallback-журнал (плоский файл) + видимый маркер пользователю.

**Инженерный фундамент** (сведён из четырёх исследований 2026-07-29 — бигтех-инфраструктура, бигтех-алгоритмы, охота «от обратного» RU + West; каждый пункт прошёл фильтр «измеримая польза / отлаживается глазами / дёшево»):

| Зона | Берём | Источник |
|---|---|---|
| Пересборка проекций | **Salsa-lite** (~200 строк над SQLite): ревизии, red-green проверка по требованию, early cutoff по хэшу значения (комментарий поменялся → ни одна проекция не пересобралась); инварианты Bazel: явно объявленные входы, ключ = hash(входов), герметичность (проекция — чистая функция фактов); порядок пересборки и детекция циклов — Pearce–Kelly | rust-analyzer/Salsa, Bazel/Buck2, «Build Systems à la Carte», Abseil |
| Схема хранения | Разведение **якорь ↔ семантический узел** (семантика стабильна, якоря волатильны и пересчитываемы); **читаемые строковые ID** `file.ts::Class::method` — урок SCIP, купленный болью LSIF; факт-тройки, малый словарь видов рёбер; у каждого факта — **владелец** (файл для слоя-1, источник доверия для слоя-2) → пересчёт файла = DELETE+INSERT по владельцу; повисший якорь — не ошибка целостности, а желаемое событие для роста отклонения | Kythe, Glean, SCIP |

| Выдача | Ленивые z-резюме (при первом визите, кэш); PPR по канону aider (буст ×50 файлам в работе, ×10 упомянутым идентификаторам, self-loop 0.1, binary search под токен-бюджет); жадный best-first по «релевантность/токен» с fan-out-лимитом, квотой разнообразия кластеров и **логом решений** («почему раскрыт узел X»); критерий anytime: контекст самодостаточен в любой момент остановки | LazyGraphRAG, aider, budgeted search |
| Поиск | SQLite FTS5: BM25 с весами колонок (имя ×10, summary ×2…) + триграммы + обязательный токенизатор идентификаторов (split camelCase/snake_case); BM25 — только генератор кандидатов, финальный скор — прозрачная линейка RRF + log(PPR) + свежесть + уверенность с ручными весами | Lucene→FTS5, Zoekt |

| Формат выдачи узла | Совпадение + дозированная AST-обвязка по уровням (объемлющие функция/класс + уровни дерева) — боевой формат grep-ast | ecom.tech |

**Чек-лист приёмки графа** (грабли чужих продакшенов, включая боевой провал graphify-подхода у прямого конкурента — [habr 1039124](https://habr.com/ru/articles/1039124/)): resolution limit Leiden (мелкие сообщества невидимы — контролировать параметр разрешения), god-узлы и «волосяные шары», авто-именованные бессмысленные кластеры, протухание индекса, корректная работа в git worktree. Всё — в критерии приёмки Этапов 0–1.

Дистрибуция: git-репозиторий = плагин + `marketplace.json`; установка `claude plugin marketplace add` + `install`. Закрытая лицензия: приватный репо (доступ по git-правам), бандл в один файл — естественная защита исходников. Все данные пользователя — локально; код никуда не уезжает (сильный пункт продажи, как у Graphify).

## 8. Анти-скоуп: что сознательно НЕ делаем

- **Зоопарк агентов** (100+ ролей ломают делегирование — острый набор по фазам, не по «специальностям»).
- **Персоны-личности** («ты — гениальный сеньор») — не добавляют точности, повышают отказы.
- **Принудительный минимум находок в ревью** — производит шум и оверинжиниринг.
- **Постоянные дебаты/панели на всём** — 4–15× цены без прироста качества.
- **Векторные БД, эмбеддинги, RAG-индексы** — staleness + инфраструктура; agentic search + структурный паспорт покрывают лучше.
- **Демоны, порты, фоновые воркеры** — источник половины issues ниши.
- **Полная церемония на каждую задачу** — «если дифф описывается одним предложением, пропусти план».
- **Парсинг внутреннего формата транскриптов** — официально нестабилен; только санкционированные интерфейсы (transcript_path из хуков, compact_summary).
- **Конкуренция с grep на one-hop** — Anthropic это уже выиграл; наше поле — multi-hop, конвенции, «why», lifecycle.

## 9. Дорожная карта

**Этап 0 — прототип майнера (проверка главного риска).** Слои 0–1 на 2 реальных репо (labreadai-v2 + рабочий проект с `var sType`-конвенциями). Критерий: ≥80% известных владельцу неписаных правил выведено с верной уверенностью, мусора <20%. Если майнер не работает — пересматриваем фундамент до постройки собора.

**Этап 1 — паспорт + подача.** Генерация паспорта, SessionStart-сводка, JIT-ретаргетинг, deferred-MCP запросный слой, handoff. Измерение: токены/задачу и качество первых ответов против голого Claude Code на тех же задачах.

**Этап 2 — принуждение.** Компиляция конвенций в ast-grep/regex-гейты, бюджеты профиля, Stop-ворота, страж фокуса. Измерение: доля нарушений конвенций в диффах до/после.

**Этап 3 — стол + петля.** Генерация ролей из профиля, симулированный стол в подаче, триггеры эскалации в панель, компаундинг уроков, обучение на поправках, ревизия памяти.

**Этап 4 — продукт.** Живучесть (деградация, heartbeat, канарейка), инициализация новых проектов (интервью), упаковка, маркетплейс, документация.

Каждый этап — работоспособный инкремент, используемый владельцем в реальной работе (dogfooding с этапа 1; сам плагин разрабатывается под управлением своего же паспорта как только это возможно).
