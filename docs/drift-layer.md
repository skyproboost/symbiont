# Слой дрейфа (Drift Layer) — концепт-заметка

> Исследовательский кластер №3. Инициатор: тестировщик владельца — «периодически
> запускаю рефактор харнесса, а то он сам потихоньку беспорядок наводит».
> Статус: концепт, заземлён на ресёрч 2026-07-30. НЕ реализован. Ждёт решения владельца.

---

## 1. Что это и почему это реальная проблема (не интуиция)

Symbiont меряет конвенции/качество проекта **в точке времени**. Слой дрейфа меряет
**производную** — куда качество движется от сессии к сессии. Это «храповик»,
сделанный **наблюдаемым и активным**: не «сейчас закон соблюдён на 100%», а «этот
закон был 100%, стал 96% за месяц — репозиторий уползает от собственной нормы».

Наблюдение тестировщика — не ощущение, а **измеренный феномен**:

- **SlopCodeBench** (arXiv 2603.24755, 2026): код AI-агентов на длинных итеративных
  задачах деградирует **монотонно** — структурная эрозия растёт в **77%** траекторий,
  многословие в **75.5%**; агентский код **в 2.0× эродированнее** и **в 2.3×
  многословнее** человеческого. «Харнесс сам наводит беспорядок» — это оно.
- Cursor-исследование (arXiv 2511.04427): «скорость ценой качества» — AI поднимает
  краткосрочную скорость и **долгосрочную сложность** в open-source.
- Silent debt: агенты плодят клоны, ревьюеры реагируют нейтрально → дубли копятся
  **незаметно** (arXiv 2601.21276). Организации с AI-долгом релизят на **50%
  медленнее**, тратят на **40%** больше на поддержку.

Вывод: инкрементальный агент **всегда** увеличивает энтропию, если нет
противодействующей силы. Symbiont и есть та сила — но сейчас он ловит только
разовые нарушения (гейт), а не **тренд**. Слой дрейфа — антитело агента к самому себе.

## 2. Ландшафт: кто как решает и где наш пробел

| Подход | Что делает | Почему не покрывает нас |
|---|---|---|
| **Fitness functions** (Evolutionary Architecture, ThoughtWorks) | исполняемые спеки архитектуры, падают в CI при нарушении | пишутся **руками** под проект; хардкод правил |
| **ArchUnit** (Java), **Deptrac** (PHP), **dependency-cruiser** (JS), **go-arch-lint** (Go), **NetArchTest** (.NET) | «домен не импортит инфраструктуру» и т.п. | **языко-специфичны**, по одному на экосистему; правила задаёт человек |
| **CodeScene** (behavioral code analysis) | анализ по **git-истории**: hotspots (частота×сложность), temporal coupling, code health trend, decay | проприетарный SaaS; облако; не в петле агента; не выводит правила проекта |
| **SonarQube** и co. | code smells, тренд долга | снапшот-центричны; шумны (см. §4); порог задаётся |

**Наш незанятый угол:** языко-агностичный, выведенный-из-проекта (ноль хардкода),
кросс-материальный (код/контент/данные), в петле агента (не отдельный SaaS),
crash-only, локальный. CodeScene — ближайший по духу (temporal, поведенческий), но
**Symbiont уже имеет половину его механик выведенными**: co-change = temporal
coupling; fix-плотность зон (constitution-derive) = hotspots; граф+PageRank =
структура; SimHash = клоны. Дрейф — это **надстройка над уже посчитанным**.

## 3. Что измерять (всё выводимо, языко-агностично, из имеющегося или дёшево из git)

Дрейф = дельта health-метрик между **снапшотами** (каждые N коммитов в
`health_snapshot`). Ни одна метрика не зашита под язык — все структурные/статистические:

1. **Эрозия конвенций** — распространённость закона падает (паспорт уже хранит
   `prevalence`; рост Glicko-отклонения = «время факта идёт быстрее»). Прямой сигнал.
2. **Поимки гейта во времени** — `gate_log`/`verify_log`: растёт ли частота нарушений
   на коммит? (данные уже копятся, нужен ряд по времени).
3. **Структурная эрозия графа** — формирование god-узлов, рост «волосяного шара»,
   **появление циклов** импортов, плотность связности HEAD vs N коммитов назад
   (граф уже строится; сравнить два).
4. **Тренд дублирования** — SimHash по блокам кода (у нас SimHash для фактов —
   расширить на код); клоны — долг №1 SlopCodeBench.
5. **Раздувание/многословие** — сдвиг распределения размеров файлов/функций вверх
   (дёшево: строки/токены во времени; SlopCodeBench меряет ровно это).
6. **Hotspot-распад** — файлы с высокой fix-плотностью **И** растущей сложностью
   (формула CodeScene: частота×сложность). fix-плотность уже есть.
7. **Дрейф контент-графа** — рост сирот/битых/дублей анкоров (entity-граф уже даёт).

Метрики универсальны: работают на Python/Go/PHP/Rust так же, как на JS, и на
контент-проектах (там дрейф = деградация перелинковки). Это и есть «глобально
индивидуально адаптивно без хардкода».

## 4. От обратного: почему такие системы проваливаются (и как мы не повторим)

Прямо из ресёрча провалов — каждый пункт уже закрыт аксиомами Symbiont:

| Грабли конкурентов | Ответ Symbiont (уже в ядре) |
|---|---|
| «вывалить кучу падающих правил → команда игнорит все» | **храповик + dry-run по умолчанию**: дрейф вводится наблюдением, гейтом — только доказанное |
| ложные срабатывания / шум линтеров | **молчание-фича**, порог уверенности, Glicko — репортим только уверенный дрейф |
| плохие данные → вводящая в заблуждение оценка | **выводим из реальности проекта**, не из абстрактного чеклиста |
| нет escape hatch → правила обходят | **предохранитель** (8 блокировок → снятие) + «если намеренно — скажи владельцу» |
| ADR/спеки пишутся и протухают руками | дрейф **выводится**, обновляется сам (петля фактов) |

## 5. Как ложится в архитектуру (симметрия, не новая махина)

- **Садовник** (гигиена знания: протухшие факты) ↔ **Слой дрейфа** (гигиена кода:
  зоны под рефактор). Идеальная пара: одна подсистема ревизует память, другая —
  указывает на код, который память уже считает уползающим.
- **Страж фокуса** (долг №7) ↔ дрейф **внутри** сессии; Слой дрейфа ↔ дрейф
  **между** сессиями.
- **/sym-elevate** (топ-1 в точке) ↔ **/sym-drift** (регрессия по тренду): elevate
  говорит «как стать лучше», drift — «где ты стал хуже с прошлого раза».

## 6. Подача (crash-only, ноль демонов — как всё в Symbiont)

- **Снапшоты health** пишутся оппортунистически (детач из Stop/SessionEnd; разовый
  на SessionStart, если давно не считался) в `health_snapshot(commit, ts, metrics_json)`.
- **Дрейф-аудит** — дельта последнего снапшота против базового; строка «дрейф» в
  `/sym-status` (молчит, если ниже порога), полный разбор — `/sym-drift`:
  худшие-уползающие зоны + предложение точечного рефактора («эти 3 файла раздулись
  на 40% и получили 2 цикла за месяц — кандидаты на тот самый периодический рефактор,
  который тестировщик гоняет вручную»).
- **Автоматизирует ручной труд тестировщика**: не «рефактор по расписанию вслепую»,
  а «Symbiont сам увидел, что беспорядок накопился, и показал ГДЕ и ЧТО именно».

## 6a. Дрейф само-образа (добавлено из разбора тулкита тестировщика, `toolkit-analysis.md`)

Дрейфует не только код — дрейфует **само-образ агента**. Findability-скилл тулкита
называет паттерн «**карта врёт**»: вход-доки описывают несуществующую архитектуру,
роутя агента в мёртвые пути. Паспорт Symbiont — это КАРТА, и он не должен подавать
вейпорвар: узел графа, которого уже нет; вытеснённую конвенцию, всё ещё в сводке;
«ключевой модуль», который удалён. Datomic-вытеснение закрывает часть, но отдельного
инварианта «**сводка = только живое**» нет. Дешёвый детерминированный чек: каждый
узел/факт сводки резолвится в существующий файл / актуальный замер; расхождение →
вытеснение + пометка. Это дрейф-метрика №8, симметричная структурному само-линту
(живучесть). Плюс findability самого знания: не осталось ли фактов, до которых
никакой канал уже не доводит (мёртвая память — frecency-порог уже частично ловит).

## 7. Инкременты (если владелец даст добро)

1. `health_snapshot` + захват 3 дешёвых метрик (эрозия конвенций, поимки-тренд,
   раздувание) + строка в `/sym-status`. Минимальный ценный срез.
2. Структурная эрозия графа (циклы, god-узлы, плотность) — на уже имеющемся графе.
3. `/sym-drift` — полный разбор + предложение рефактора (стиль elevate).
4. SimHash-клоны кода + hotspot-распад (частота×сложность).
5. Дрейф контент-графа (сироты/битые во времени).
