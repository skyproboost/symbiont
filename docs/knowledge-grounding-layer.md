# Слой заземления знания (Knowledge Grounding Layer) — концепт-заметка

> Исследовательский кластер №5 (расширенный). Запрос владельца: покрыть ВЕСЬ SDLC
> (разработка/качество/безопасность/тесты/выкатка/БД/девопс/ревью) и оставаться
> идеально адаптивным к чему угодно новому — новый язык, фреймворк, методология,
> формула, дизайн, даже просто рассуждение — абстрактно, без хардкода.
> Статус: концепт, заземлён на ресёрч 2026-07-30. НЕ реализован.

---

## 1. Точный диагноз: у Symbiont два знания, адаптивно только одно

- **Знание ВНУТРЬ** (реальность проекта): конвенции, граф, профиль, прецеденты.
  Уже **выводится, само-обновляется, ноль хардкода** — петля фактов + Glicko/FSRS.
  ✅ Решено.
- **Знание НАРУЖУ** (экспертиза мира: стандарты, фреймворки, методологии):
  `playbooks.ts` (БД/nginx/фронт/SEO/TLS/деплой), `rubric.ts` (ISO 25010/CWV/WCAG/
  OWASP/DAMA). Сейчас — **курируемая библиотека, замороженная в момент написания**.
  ❌ Протухнет: выйдет новый фреймворк — молчим; CWV поменяет порог, OWASP выпустит
  новый Top-10, Let's Encrypt уедет с 90 на 45 дней — паспорт этого не узнает.

Запрос владельца = **сделать знание НАРУЖУ таким же адаптивным, как ВНУТРЬ.**

Это ровно тот пробел, что ресёрч называет главным ограничением всех LLM-агентов:
«**заморожены во времени** — не учатся новым технологиям, ломающим изменениям,
эволюции best-practices → knowledge drift» (arXiv 2607.13091, 2510.09721).

## 2. Ландшафт и подтверждение архитектуры (мы на правильном пути)

| Подход/находка | Что говорит | Связь с Symbiont |
|---|---|---|
| **LintCFG** (LLM-компиляция стандартов в правила, **независимо от языка/линтера**) | не держи по генератору на язык — LLM адаптирует | ровно «ноль хардкода под язык»; наш слой 2 + будущий долг №9 |
| **CodeRabbit universal linter** (RAG + **ast-grep** + LLM) | детерминированный AST даёт факты, LLM — контекст | **у нас уже так**: tree-sitter (слой 1) + LLM-вербализация (слой 2) |
| **Self-Improving Agents via Accumulated Behavioral Rules** (arXiv 2607.13091) | замкнутая петля правил из наблюдений | наша петля поправок — академически подтверждена |
| **Agents rewrite own skills without retraining** (Memento-Skills) | навык как исполнимый артефакт, эволюционирует | плейбук-на-лету (v0.36) — зачаток |
| **graph traversal > pure vector search** | ретрив, понимающий СВЯЗИ, а не только похожесть | у нас граф, не эмбеддинги — уже правильно |

**От обратного — почему конкуренты не тянут (и почему мы можем):**

| Провал | Ответ Symbiont |
|---|---|
| модель заморожена → не знает нового | `ground.ts` (WebSearch) заземляет на **актуальные** источники + FSRS-старение фактов |
| RAG не учится сессия-к-сессии (поймал ошибку — повторит) | хуки + петля поправок = ровно эта память между сессиями |
| «When More Retrieval Hurts» (2511.05302) — лишний ретрив шумит | JIT-минимализм, молчание-фича, deferred-MCP |
| курируемые правила протухают | курируемое = **сид, не потолок** (см. §3) |

## 3. Дизайн: LLM как универсальный адаптер к новизне, детерминизм — быстрый путь к известному

Единый принцип, покрывающий «всё» БЕЗ перечисления всего:

> **Обнаружение → если известно, быстрый детерминированный путь; если ново —
> LLM заземляет из актуальных источников и кэширует как СТАРЕЮЩИЙ факт.**

Покрытие всего SDLC достигается не энциклопедией в ядре, а **композицией трёх сил**,
каждая из которых уже частично есть:

1. **Универсальные оси качества по материалу** (`artifacts.ts` + `rubric.ts`):
   активируются самим составом проекта (код/контент/дизайн/данные/инфра) — работают
   на любом материале, включая «просто дизайн» и «просто рассуждение» (ось
   легитимность/связность/полнота применима и к тексту).
2. **Генеративные доменные плейбуки** (эволюция `playbooks.ts` + `ground.ts`):
   курируемые плейбуки — быстрый путь для частого; для ЛЮБОГО обнаруженного, но
   некурируемого направления/фреймворка/языка — плейбук **синтезируется на лету**
   заземлением на актуальные источники и **кэшируется как факт** с Glicko/FSRS.
   Незнакомая технология (`otherDeps`) → триггер заземления, а не молчание.
3. **Выведенная реальность проекта** (уже есть): как ЭТО направление устроено
   ИМЕННО ЗДЕСЬ (слои 0–2).

### Три конкретных механизма (каждый — эволюция существующего)

**(A) Курируемое как сид, не потолок.** `PLAYBOOKS`/`RUBRIC` остаются быстрым
дефолтом, но получают поле `groundedAt` и срок годности (FSRS). Просрочено или
затронуто некурируемое направление → `ground.ts` до-заземляет и кэширует. Порог
доверия к заземлённому — Glicko (какие внешние факты реально подтверждаются работой).

**(B) Петля ре-заземления стандартов** (дрейф знания НАРУЖУ — симметрия слою дрейфа
кода). Триггерно/crash-only: «CWV всё ещё LCP≤2.5с? OWASP всё ещё Top-10:2025? срок
LE всё ещё 45д?» — периодическая сверка курируемых порогов с источником; изменилось
→ вытеснение факта (Datomic) + пометка в сводке. Заморозку лечим не разовым ручным
апдейтом кода, а живой петлёй.

**(C) Универсальный компилятор правил** (сходится с долгом №9 + LintCFG + CodeRabbit):
слой 2 уже вербализует правила прозой; следующий шаг — компиляция выведенного/
заземлённого правила в исполнимый чек (ast-grep где есть грамматика, regex-фолбэк),
**независимо от языка**. «Наблюдённая проблема → исполнимое ограничение → гейт» —
петля само-исцеления (подтверждена Agent-Native Development).

## 4. Почему это покрывает «крч всё» без хардкода

- **Новый язык** → tree-sitter (~40 грамматик) + универсальный слой 0 + слой 2
  вербализует его идиомы; сигнал детектится по манифесту/расширению.
- **Новый фреймворк** → `otherDeps` делает его видимым; ground-плейбук синтезируется.
- **Новая методология/формула/архитектура** → приходит через ре-заземление rubric/
  плейбуков (петля B); rubric — данные, не код.
- **Просто дизайн / просто текст / рассуждение** → оси по материалу (artifacts) +
  универсальные оси (связность/полнота/легитимность) активируются составом.
- **Безопасность/тесты/деплой/БД/девопс/ревью** → каждое — направление с сигналом;
  известное = курируемый плейбук, новое = заземлённый. Ревью = `/sym-elevate` уже
  применяет оси+принципы+заземление к чему угодно.

Ядро остаётся крошечным (сигналы + сиды + оси); **адаптивность к новизне несёт
LLM-заземление поверх, детерминизм — быстрый путь к уже освоенному.** Ноль хардкода
про конкретную технологию сохраняется.

## 5. Инкременты (если владелец даст добро)

1. `groundedAt` + FSRS-срок на плейбуках/рубрике; истекло/некурируемое → авто-ground
   с кэшем-фактом (малый, высокоценный).
2. Ре-заземление триггерно (crash-only детач; строка «знание освежено» в /sym-status).
3. Универсальный компилятор правил (ast-grep + regex) — сходится с долгом №9.
4. Glicko на внешних фактах (какие заземления реально подтверждаются работой).
